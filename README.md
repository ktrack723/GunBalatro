# GunBalatro (가제: **THE LITANY** / 연도)

> 1인칭 · three.js · 모바일 세로 우선 · GitHub Pages 정적 호스팅
> **발라트로의 덱빌딩 수학**을 **볼터 라이플의 탄약 관리**로 번역한 로그라이크 슈터.

---

## 한 줄 정의

> 어두운 폐건물 골목을 자동으로 전진하며, **가방에서 뽑은 탄을 탄창에 어떤 순서로 넣을지** 결정해
> 다가오는 좀비를 **닿기 전에** 사살하는, 순서(order)가 곧 수학인 1인칭 덱빌딩 슈터.

> **v2 가 v1 과 다른 점**: 발라트로에 비유하면 *"핸드를 하이카드로 고정해 두고
> 조커만으로 굴리는 게임"* 이다. 덱 무작위성이 사라진 자리에 **부착물 조합**과
> **특수탄을 언제 쓰는가**가 들어왔다. 온도는 탄창마다 초기화되지 않고
> **사격 사이 50% 이월**되므로, "언제 큰 걸 쏘는가"가 한 탄창을 넘어 전투 전체로 확장된다.
> 그 대가로 배열 격차가 줄어들기 때문에(BALANCE §7.5 법칙 1),
> **온도가 낮을수록 강해지는 탄**을 반대 추로 두어 "올릴까 식힐까" 자체를 선택으로 만들었다.

## 설계 3원칙

1. **모든 파라미터는 결정을 만든다.**
   플레이어가 신경 쓰는 숫자가 늘어나는 비용은, 그 숫자가 만들어내는 *선택*으로만 정당화된다.
   결정을 만들지 않는 수치(명중률·반동·탄속·스태미나 등)는 전부 삭제했다.
2. **곱셈은 오직 하나 — 온도.**
   데미지는 덧셈으로만 자란다. 온도도 덧셈으로만 자란다. 최종 계산에서 단 한 번 곱한다.
   "얼마나 예열하고 언제 큰 걸 쏘는가"가 게임의 전부다.
3. **순서(order)가 1급 시민이다.**
   발라트로에서 카드 순서는 대부분 무의미하다. 여기서는 온도가 발사마다 누적되므로
   **동일한 5발을 어떤 순서로 넣느냐가 데미지를 3~10배 갈라놓는다.** 이것이 이 게임의 존재의의다.

## 실행

```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm run build      # 정적 빌드 → dist/
npm test           # 코어 규칙 단위 테스트 225개
npm run sim        # 헤드리스 밸런스 시뮬레이터 (성공 기준 6개 자동 판정)
```

- `#seed=1234` 또는 `#seed=아무문구` — 같은 판 재현
- `#dev` — fps / 드로우콜 / 삼각형 / DPR / 품질 오버레이

배포는 `main` 브랜치 푸시 시 GitHub Actions 가 GitHub Pages 로 자동 배포한다
(`.github/workflows/deploy.yml`). base 는 `'./'` — 산출물이 어느 하위 경로에 놓여도 동작한다.

> **⚠ Pages 소스 설정을 바꿔야 한다 (한 번만).**
> 현재 저장소의 Pages 소스가 **Deploy from a branch (main / root)** 로 되어 있어서,
> 푸시할 때마다 워크플로와 별개로 GitHub 의 Jekyll 빌더가 **저장소 루트를 그대로** 서빙한다.
> 루트 `index.html` 은 Vite 개발용 진입점이라 `/src/main.ts`(TypeScript)를 가리키고,
> 브라우저는 그걸 실행하지 못한다 → **흰 화면**. 게다가 Jekyll 배포가 워크플로 배포보다
> 20초쯤 늦게 끝나서 항상 이쪽이 이긴다.
>
> **영구 해결:** Settings → Pages → Build and deployment → Source 를 **GitHub Actions** 로 바꾼다.
>
> 그때까지의 임시 조치로 (a) `dist/` 를 저장소에 커밋해 두고, (b) 루트 `index.html` 이
> `*.github.io` 에서 열렸을 때 `./dist/` 로 넘긴다. 소스를 GitHub Actions 로 바꾸면
> 서빙되는 건 `dist/index.html` 이라 이 리다이렉트는 로드되지도 않으므로,
> 그 시점에 `dist/` 추적과 워크플로의 'dist 갱신' 스텝, 루트 `index.html` 의
> `PAGES_REDIRECT` 블록을 지우면 된다.

## 보상방

전투를 이기면 **탄피 · 특수탄 · 부착물 3택** 이 놓인 방이 열린다. 셋을 각각 눌러서
가져가며(슬더스식), 부착물만 그 자리에서 세 장 중 하나를 고른다. 예전에는 3~4장 중
하나만 고르고 나머지가 사라졌다 — 탄피는 자동으로 들어오고 특수탄은 '부착물 대신
고르는 것' 이라, 이기고도 무언가를 버리는 화면이었다.

### 밸런스 실측 (400런 · 성전 등급 1)

greedy 봇 **36.5%** / optimal 봇 **39.0%** 클리어 (200런).
성공 기준 5개 중 **4개 통과**.

- ✅ 순서 민감도 — 첫 탄창 **5.81배**, 이월된 탄창 **2.64배** (목표 2.5배)
- ✅ 갈림길 위험도3 선택률 43.9% (목표 35~65%)
- ✅ 숙련도 격차가 섹터마다 벌어짐
- ✅ 승률 밴드 28~42%
- ❌ 채택 0회 부착물 1종

> **이월 50% 의 대가가 측정된다**: 온도가 사격 사이 이월되면 시작 온도가 높아지고,
> 그만큼 탄창 안의 배열 격차가 줄어든다(5.81배 → 2.64배).
> 이것이 [docs/BALANCE.md §7.5](docs/BALANCE.md) 법칙 1 이 예측한 그대로다.
> 저온 특화 탄·부착물이 그 반대 추다.

## 구현 메모

- `src/core/` 는 three.js·DOM 을 전혀 모른다. `combat.fire()` 가 **이벤트 로그**를 반환하고
  `sequencer/` 가 그것을 연출로 번역만 한다 → 헤드리스 밸런싱, 연출 속도 ×1/×2/×3/즉시,
  실시간 예상 피해가 전부 같은 코드 경로에서 나온다.
- 모든 무작위는 `mulberry32(seed)` 단일 스트림. `Math.random()` 은 게임 로직에 0회.
  연출용 난수는 완전히 분리된 스트림이다.
- 포스트프로세싱 체인 대신 **풀스크린 쿼드 1장 + uniform 5개**로 플래시·색수차·비네트·열왜곡 처리.
