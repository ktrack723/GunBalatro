| 항목 | 내용 |

| 시점 | 1인칭 고정. 이동은 자동(온레일), 전투는 정지 상태 |
| 플랫폼 | 웹 (three.js / WebGL2). **iPhone Safari 세로 모드 1급 지원** |

| 조작 | 터치 전용. 탭 · 드래그(순서 배치) · 롱프레스(정보) |

### 세계관 요약 (기획 최소치)

인류는 무너졌다. 당신은 **성전 사수(Litanist)** — 볼터 라이플 한 자루와, 성별(聖別)되지 않은 잡탄이 뒤섞인
가방 하나를 들고 끝없이 이어지는 폐건물을 내려간다. 총열이 뜨거울수록 총은 기도에 응답한다.
탄약은 유한하지 않다(회수 가능). 유한한 것은 **거리**다.

> 세계관은 규칙에 봉사하는 최소한만 존재한다. 총열 온도 = 신앙의 은유, 거리 = 죽음까지의 카운트다운.

## 2. 코어 루프

```
[섹터 시작]
   │
   ├─▶ ① 온레일 전진 (8~15초, 1인칭 자동 이동, 스킵 가능)
   │        복도 · 계단 · 무너진 사무실을 지나며 갈림길 문 2개가 보인다
   │
   ├─▶ ② 갈림길 선택 (문 A: 쉬움/저레어도  vs  문 B: 어려움/고레어도)
   │
   ├─▶ ③ 전투 (아래 전투 루프)
   │
   ├─▶ ④ 보상방 (부착물 or 탄 3택 1 무료 + 탄피 정산)
   │
   └─▶ ①로. 4노드 진행 후 섹터 보스 → 다음 섹터
```

### 전투 루프 (핵심)

```
전투 시작
  ├ 가방 셔플 → 트레이에 8발 드로우
  ├ 거리 = 적의 시작 거리 (예: 30m)
  │
  └▶ [행동 페이즈] ─ 아래 둘 중 하나 선택, 거리가 남아있는 한 반복
        │
        ├─(A) 장전 & 사격
        │      1. 트레이에서 탄창 용량(기본 5)까지 탭 → 탭한 순서가 곧 장전 순서
        │      2. 순서 재배치 가능(드래그) / 확정 전까지 무료
        │      3. [사격] 버튼 → 온도 1.00으로 초기화
        │      4. 1번 탄부터 순차 발사. 매 발사마다 데미지 파이프라인 1회전
        │      5. 탄창이 비면 사격 종료 → 온도 소멸(기본 규칙)
        │      6. 거리 −= 적의 접근 속도 S
        │      7. 트레이를 8발까지 재보충
        │
        └─(B) 배출 (Eject / 발라트로의 버리기)
               1. 트레이에서 최대 3발 선택 → 배출
               2. 거리 −= ceil(S / 2)
               3. 트레이 재보충
  │
  ├ 적 HP ≤ 0  → 승리 → 보상방
  └ 거리 ≤ 0   → 좀비 접촉 → 즉사 → 런 종료
```

**핵심 긴장**: 한 번의 사격도 한 번의 배출도 좀비를 앞으로 당겨온다.
"패를 고르는 데 쓰는 비용"과 "죽음까지의 시간"이 **동일한 게이지**다.

## 3. 자원 모델 — 세 개의 숫자만 본다

플레이어가 화면에서 추적해야 하는 숫자는 **정확히 3개**다. 이것이 파라미터 예산의 전부다.

### 3.1 거리 (DIST, m) — "얼마나 더 할 수 있는가"

- 발라트로의 *핸드 수 + 버리기 수*를 하나로 합친 것.
- 좀비마다 **접근 속도 S (m/행동)** 가 다르다.
  - 사격 행동: `DIST -= S`
  - 배출 행동: `DIST -= ceil(S / 2)`
- `DIST ≤ 0` → **즉사**. HP 개념이 없다. 체력바가 없으니 "조금씩 깎이는 안전마진"이라는 흐릿한 감각이 없고,
  매 행동이 명확한 카운트다운이다.
- **왜 미터인가**: 3D 화면에서 좀비가 실제로 그만큼 다가온다. 숫자와 시각이 1:1이라 UI 학습 비용이 0에 수렴한다.

> **설계 의도**: 발라트로의 "핸드 4 / 버리기 3"은 서로 다른 두 개의 정수 자원이라 초심자에게 부담이다.
> 하나의 연속 게이지로 통합하면 **"이 배출이 사격 반 번어치 가치가 있는가"** 라는 질문이 매 순간 자동으로 생긴다.
> 게다가 적의 이동속도라는 **전투마다 달라지는 축**을 공짜로 얻는다. (빠른 적 = 행동 수가 적다)

### 3.2 총열 온도 (HEAT) — "곱수"

- 사격 시작 시 **1.00** (탄창/부착물이 이 시작값을 바꿀 수 있다).
- 탄과 부착물이 **덧셈으로만** 온도를 올린다. `HEAT += x` 만 존재한다. `HEAT *= x` 는 게임에 존재하지 않는다.
- **탄창을 비울 때까지 유지**된다. 즉 한 번의 사격 행동 안에서만 누적된다. (기본 규칙 — 일부 탄창/부착물이 이월시킨다)
- 총 스프라이트가 온도에 따라 강철 → 암적 → 주황 → 노랑 → 백열로 변한다. (PRESENTATION.md 참조)

> **왜 x멀트를 없앴는가**: 발라트로의 +Mult/×Mult 이중 구조는 강력하지만, 초보자가 "×를 먼저 곱해야 하나"를
> 계속 헷갈리게 만든다. **곱셈 축이 하나뿐이면 최적 전략이 항상 "약한 순 → 강한 순"으로 단순 서술된다.**
> 그 위에 부착물이 예외를 만드는 구조가 훨씬 배우기 쉽고 파고들기는 똑같이 깊다.

### 3.3 데미지 (DMG) — "곱해질 것"

- 탄이 가진 고유값. 부착물이 **덧셈으로만** 보정한다.
- 화면에는 발사 순간에만 잠깐 뜬다 (칩 팝업). 상시 추적 대상이 아니다.

### 3.4 (보조) 탄창 용량 · 트레이 크기 · 탄피

전투 중에는 거의 변하지 않는 준정적 수치. HUD 상시 노출은 아이콘 + 작은 숫자로만.

## 4. 데미지 파이프라인 (정확한 연산 순서)

한 발을 쏠 때마다 아래 7단계가 **정확히 이 순서로** 1회전한다.
이것이 발라트로의 "핸드 채점"에 대응하며, 탄창 5발 = 채점 5회전이다.

```
── 발사 n번째 탄 R ──────────────────────────────

STEP 1  기본 데미지
        dmg  ←  round( 등급기본치[R.grade] × 탄종계수[R.type] )

STEP 2  탄 고유 온도
        heatGain ← 탄종온도[R.type](R.grade)

STEP 3  부착물 데미지 보정 (덧셈만)
        하드포인트 순회 순서: 총열 → 총열덮개 → 광학 → 개머리판 → 보조레일(좌→우)
        각 부착물의 onFire 훅에서  dmg += k

STEP 4  부착물 온도 보정 (덧셈만)
        같은 순회 순서로  heatGain += k

STEP 5  온도 확정 & 적용
        HEAT ← HEAT + heatGain          ← ★ 자신이 올린 온도는 자신에게도 적용된다
        damage ← round( dmg × HEAT )

STEP 6  적 방어 패시브 적용
        damage ← 적패시브(damage, n, R)   (경감 / 무효 / 반사 등)
        적HP  -= damage

STEP 7  발사 후 훅
        - 누적형 부착물 카운터 갱신 (예: "HE 명중마다 +30 영구")
        - 탄 소모 판정 (탄창 특수효과로 소모되지 않을 수 있음)
        - 넉백(HE) → DIST += 넉백값
        - 다음 탄 예약 버프(축성탄) 등록
─────────────────────────────────────────────────
```

### 4.1 STEP 5의 ★ 규칙이 중요한 이유

**자신이 올린 온도가 자신에게 적용된다.** 즉 소이탄은 "다음 탄을 위한 죽은 카드"가 아니라 자기 몫도 챙긴다.
그럼에도 온도는 누적되므로 **큰 데미지 탄을 뒤로 미루는 것이 여전히 최적**이다.
→ "예열 후 피니셔"라는 직관적 최적해가 성립하면서, 예열탄이 심리적으로 낭비처럼 느껴지지 않는다.

### 4.2 순회 순서를 명시하는 이유

부착물끼리 조건이 겹칠 때(예: "직전 탄과 같은 탄종이면" + "탄 데미지 +") 결과가 결정론적이어야 한다.
**부착물은 좌→우로 재배치 가능**하며, 순서 자체가 플레이어의 결정이 된다 (발라트로 조커 순서와 동일 철학).
단, 하드포인트는 부위가 고정이므로 실질적으로 순서 조정이 가능한 것은 **보조 레일 슬롯 사이**다.

## 5. 탄 (Ammo)

탄 1발 = **탄종(Type) × 등급(Grade)**. 발라트로의 슈트 × 랭크에 정확히 대응한다.

### 5.1 탄종 4종 — 각각의 존재의의

| 탄종 | 역할 한 줄 | 데미지 계수 | 온도 획득 | 고유 효과 |
|---|---|---|---|---|
| **철갑 (AP)** | *곱해질 것* | ×1.7 | +0.1 | 없음 (순수 피니셔) |
| **소이 (INC)** | *곱할 것* | ×0.45 | +0.5 + 0.25×G | 없음 (순수 예열) |
| **고폭 (HE)** | *시간을 벌 것* | ×1.0 | +0.3 | 발사 시 **거리 +0.5×G m** (넉백) |
| **축성 (SANC)** | *엮을 것* | ×0.7 | +0.4 | ① 다음 발사 탄의 데미지 **+20×G**<br>② 부착물 조건 판정에서 **모든 탄종으로 취급 (와일드)** |

> **네 개면 충분하고 네 개여야 하는 이유**
> 곱셈 게임에서 필요한 최소 역할은 (a) 곱수 생성 (b) 곱해질 큰 값 (c) 자원 확보 (d) 조합 접착제 — 정확히 4개다.
> 5번째 탄종은 이 중 하나의 열화판이 되거나, 플레이어의 색 인지 부담만 늘린다. 그래서 넣지 않았다.

**축성탄의 와일드 규칙**이 발라트로의 와일드 카드/스톤 카드 역할을 하며, 조건부 부착물 빌드의 안정성을 담당한다.
축성탄 없이 "탄종 3종 이상이면" 같은 조건은 운에 지나치게 좌우된다.

### 5.2 등급 5단계

| 등급 | 표기 | 기본 데미지 B(G) | 획득 난이도 |
|---|---|---|---|
| 1 | Mk.I | 10 | 시작 가방 다수 |
| 2 | Mk.II | 20 | 시작 가방 소수 / 흔한 보상 |
| 3 | Mk.III | 34 | 중반 보상 |
| 4 | Mk.IV | 52 | 후반 보상 / 승급 |
| 5 | Mk.V | 75 | 희귀. 승급으로만 안정 확보 |

> 13랭크가 아니라 5등급인 이유: 세로 화면 카드 가독성. 카드 한 장에 **아이콘(탄종) + 로마숫자(등급)** 두 정보만 담아
> 24×36pt 크기에서도 즉시 판독되게 한다. 또한 "등급 비교" 조건 부착물(오름/역순)의 경우의 수를 인간이 셀 수 있는 범위로 유지한다.

### 5.3 실제 탄 스탯 (계산 완료)

| | Mk.I | Mk.II | Mk.III | Mk.IV | Mk.V |
|---|---|---|---|---|---|
| **철갑 AP** | 17 dmg / +0.1 | 34 / +0.1 | 58 / +0.1 | 88 / +0.1 | 128 / +0.1 |
| **소이 INC** | 5 / **+0.75** | 9 / **+1.00** | 15 / **+1.25** | 23 / **+1.50** | 34 / **+1.75** |
| **고폭 HE** | 10 / +0.3 / **+0.5m** | 20 / +0.3 / **+1.0m** | 34 / +0.3 / **+1.5m** | 52 / +0.3 / **+2.0m** | 75 / +0.3 / **+2.5m** |
| **축성 SANC** | 7 / +0.4 / *다음탄 +20* | 14 / +0.4 / *+40* | 24 / +0.4 / *+60* | 36 / +0.4 / *+80* | 53 / +0.4 / *+100* |

### 5.4 가방 (Bag)

- **시작 구성 24발** — BALANCE.md §2 참조.
- 전투 시작 시 셔플 → 트레이 8발 드로우.
- 발사/배출된 탄은 **소각 더미(Spent)** 로 간다.
- **가방이 비면 소각 더미를 전부 회수해 재셔플** ("탄약 재보급"). 덱이 마르는 데드엔드를 원천 차단.
  → 발라트로와 달리 여기서는 덱 사이즈가 "탄약 고갈 위험"이 아니라 **"원하는 탄이 나올 확률"** 만을 의미한다.
  덱 압축(Thinning)의 가치가 순수하게 확률 문제로 정리된다.

## 6. 탄창 (Magazine) — 규칙 변경자

**동시에 1개만 장착.** 발라트로의 바우처보다 훨씬 강한, 빌드의 정체성 그 자체다.
"몇 발 넣는가"가 곧 "곱셈을 몇 번 굴리는가"이기 때문에 탄창 교체는 항상 큰 결정이다.

| # | 이름 | 용량 | 효과 | 설계 의도 (무엇을 가능케 하는가) |
|---|---|---|---|---|
| M1 | **표준 5연발** | 5 | — | 기준선. 모든 밸런스의 원점 |
| M2 | **드럼 8연발** | 8 | 모든 온도 획득 **−30%** (버림 아님, 소수 유지) | *폭(width)* 빌드. 데미지 덧셈이 많을 때 유리 |
| M3 | **탐식의 성궤** | 2 | 발사한 탄이 **75% 확률로 소모되지 않음** | *고분산* 빌드. 기대 8발, 실제 2~20발. 도박형 |
| M4 | **정밀 3연발** | 3 | 발사할 때마다 추가로 **온도 +1.5** | *깊이(depth)* 빌드. 적은 탄으로 온도 극대화 |
| M5 | **무한 벨트** | 7 | 트레이 **−2** (6발) | 선택지를 줄이는 대신 곱셈 횟수를 늘림 |
| M6 | **성궤 탄창** | 4 | **축성탄의 ①효과가 2회 적용** (즉 다음 탄 데미지 +40×G) | 축성 특화 빌드의 축 |
| M7 | **냉각 자켓** | 5 | 사격 종료 시 **온도의 40%를 다음 사격으로 이월** | 유일하게 "온도 이월"을 여는 탄창. 장기전 빌드 |
| M8 | **역장 급탄기** | 5 | 사격 행동의 **거리 소모 −2m** | 자원 빌드. 빠른 적 카운터 |
| M9 | **처형자 (단발)** | 1 | 사격 시작 온도가 **12.00**. 사격 행동 거리 소모 **−2m** | 극단. 한 발에 모든 것을 거는 빌드 |
| M10 | **참회의 탄대** | 6 | 첫 발의 데미지 **0**. 이후 모든 발사 온도 **+2.0** | "첫 탄은 제물" — 순서 설계를 강제하는 탄창 |

> **왜 x멀트 없이도 탄창이 강한가**: 탄창은 수치가 아니라 *구조*(용량·소모규칙·이월·자원)를 바꾼다.
> 구조 변경은 수치 인플레 없이 빌드를 갈라놓는 가장 저렴한 방법이다.

## 7. 부착물 (Attachment)

발라트로의 조커. **상세 목록과 레어도 철학은 [ATTACHMENTS.md](ATTACHMENTS.md)** 에 있다. 여기서는 구조만.

### 7.1 슬롯 구조

| 슬롯 | 개수 | 담당 축 | 왜 부위를 고정하는가 |
|---|---|---|---|
| **총열 (Barrel)** | 1 | 데미지(칩) | 총 한 자루에 총열은 하나. 물리적 직관 = 학습 비용 0 |
| **총열덮개 (Handguard)** | 1 | 온도(멀트) | 방열 부품 = 온도라는 연상이 자동으로 성립 |
| **광학 (Optic)** | 1 | 정보 / 거리 | "본다"는 행위 = 미리보기·사거리 |
| **개머리판 (Stock)** | 1 | 자원 / 경제 | 안정성·휴대 = 거리·탄피·트레이 |
| **보조 레일 (Rail)** | 0 → 최대 2 | 자유 (조건·콤보) | 확장 슬롯. 성물/각인류. 순서 재배치 가능 |

최대 동시 장착 **6개**. 시작 시 하드포인트 4개는 비어 있고 보조 레일은 0개다.

> **왜 발라트로처럼 자유 5슬롯이 아닌가**
> 자유 슬롯은 "데미지 부착물 5개 쌓기"라는 지배 전략을 낳는다. 이 게임은 곱셈 축이 하나뿐이라
> 발라트로보다 그 위험이 훨씬 크다. **부위 고정은 데미지 1 : 온도 1 : 자원 1 : 정보 1 비율을 강제**하고,
> 그 결과 모든 런이 "네 축을 각각 어떻게 채울까"라는 동일하고 명료한 퍼즐이 된다.
> 자유도는 보조 레일 2칸과 부착물 자체의 조건 다양성으로 확보한다.

### 7.2 부착물이 건드릴 수 있는 것 (효과 문법)

부착물 효과는 아래 **8개 동사**로만 기술된다. 이보다 늘리지 않는다.

| 동사 | 형태 | 예 |
|---|---|---|
| `DMG+` | 발사되는 탄의 데미지 +k | 연장 총열 |
| `HEAT+` | 온도 획득 +k | 방열 핀 |
| `HEAT_START+` | 사격 시작 온도 +k | 순교의 화로 |
| `DIST+` / `DIST_COST−` | 거리 확보 / 행동 비용 감소 | 거리계 |
| `TRAY±` / `CAP±` | 트레이·탄창 용량 변경 | 예비 탄창 |
| `BAG` | 가방/트레이 조작(생성·변환·소환·승급) | 예지 렌즈 |
| `BRASS+` | 탄피 획득 | 전리품 벨트 |
| `SLOT+` | 슬롯 확장 | 성유물 거치대 |

각 동사에 **조건절(when)** 이 하나 붙는다. 조건절도 아래로 제한한다.

`항상` / `탄종이 X면` / `등급이 N 이상이면` / `직전 탄과 같은(다른) 탄종이면` /
`직전 탄보다 등급이 높은(낮은) 탄이면` / `탄창의 첫(마지막/N번째) 탄이면` /
`온도가 T 이상이면` / `거리가 D 이하(이상)면` / `이번 탄창에 탄종이 K종 이상이면`

→ **동사 8 × 조건 11**. 이 조합표 위에서만 설계하므로 툴팁 문장이 항상 한 줄에 들어가고,
플레이어는 새 부착물을 봐도 읽는 법을 새로 배울 필요가 없다.

## 8. 적 (Zombie)

### 8.1 적이 가진 파라미터는 4개뿐

| 파라미터 | 의미 | 플레이어의 결정에 미치는 영향 |
|---|---|---|
| **HP** | 발라트로의 블라인드 점수 | 목표치 |
| **접근 속도 S (m/행동)** | 사격 1회당 줄어드는 거리 | 총 행동 횟수 = 배출 여유 |
| **시작 거리 D₀ (m)** | 전투 시작 거리 | 위와 결합해 행동 횟수 결정 |
| **패시브 (0~1개)** | 규칙 왜곡 | 탄창 구성 방식 자체를 바꿈 |

> 공격력·명중률·경직·상태이상 같은 건 없다. 좀비는 **닿으면 즉사**뿐이므로 전투 결과가 항상 이분법이고,
> 플레이어는 "이 전투를 몇 행동 안에 끝내야 하는가" 하나의 질문에만 답하면 된다.

### 8.2 아키타입 (일반 적)

| 아키타입 | HP | S | D₀ | 성격 |
|---|---|---|---|---|
| **배회자 (Shambler)** | 기준 ×1.0 | 5 | 30 | 표준. 6행동 |
| **주자 (Runner)** | ×0.55 | 10 | 32 | 3행동. 폭발적 단기 화력 요구 |
| **비대체 (Bloat)** | ×1.8 | 3 | 26 | 8행동. 긴 예열 빌드 보상 |
| **무리 (Horde)** | ×1.3 | 6 | 34 | HP 공유. 시각적으로 다수, 규칙상 1개체 |
| **기어다니는 것 (Crawler)** | ×0.7 | 4 | 18 | 시작 거리가 짧다. 근거리 부착물 활성 |

> **무리(Horde)를 "HP 공유 단일 개체"로 만든 이유**: 좀비 아포칼립스 비주얼에 군집은 필수지만,
> 다중 타겟은 "관통·스플래시·타겟팅"이라는 파라미터 3개를 강제로 데려온다. 비용 대비 리턴이 없다.
> 그래서 **연출은 다수, 규칙은 단일**로 분리했다. 마지막 발에 여러 마리가 한꺼번에 쓰러진다.

### 8.3 패시브 (엘리트 / 섹터 보스) — 발라트로 보스 블라인드 대응

| 패시브 | 효과 | 강제하는 플레이 변화 |
|---|---|---|
| **강직 (Rigid)** | 탄창의 **2번째 탄** 데미지 0 | 순서 재설계. 2번 자리에 예열탄을 버린다 |
| **장갑 (Plated)** | 매 사격의 **첫 2발** 데미지 50% | 앞을 버리고 뒤에 몰아넣기 |
| **돌진 (Lunge)** | 사격 행동 후 추가 **−4m** | 행동 수 압박. 배출 포기 |
| **냉혈 (Coldblood)** | 온도 **획득 −40%** | 데미지 덧셈 빌드로 전환 |
| **재생 (Regen)** | 사격 사이 HP **+4%** | 시간 끌기 금지. 한 방 빌드 요구 |
| **역병 (Plague)** | 사격 종료 시 가방에서 무작위 1발 **소멸(전투 한정)** | 장기전 페널티. 압축 덱에 더 아픔 |
| **암흑 (Blind)** | 트레이 8발 중 **4발이 뒷면**. 장전 확정 시 공개 | 정보 부착물의 가치 급등 |
| **성별 거부 (Anathema)** | **축성탄** 데미지 0, 와일드 판정 불가 | 축성 의존 빌드 견제 |
| **열역학 (Entropy)** | 온도가 **20을 넘으면 그 사격 즉시 종료** | 과열 빌드에 상한. 폭 빌드로 전환 |
| **포식 (Devour)** | 매 사격 시작 시 트레이에서 **가장 데미지 높은 탄 1발 제거** | 안정적 분산 구성 요구 |

> 각 패시브는 **정확히 하나의 축을 봉쇄**한다: 순서 / 앞부분 / 자원 / 온도 / 시간 / 덱 / 정보 / 특정 탄종 / 상한 / 최고치.
> 봉쇄 축이 겹치는 패시브는 만들지 않는다. 10개면 9섹터를 중복 없이 채우고도 남는다.

## 9. 런 구조

### 9.0 지역 (Region) — 런을 세 덩어리로 자른다

섹터는 여덟 개가 전부 똑같이 생긴 복도였다. 숫자만 올라가고 **어디에 있는지**는
달라지지 않으니, 다 걸어도 한 자리에 있는 것 같았다. 지역은 그 구간에 얼굴을 준다.

```
런 = 3지역 × 3섹터 = 섹터 1 ~ 9   (엔드리스 모드는 10+ 계속)

지역 1  섹터 1~3   「강철 하복부」  차갑고 어둡다. 손전등이 정보의 전부다.
지역 2  섹터 4~6   「노란 층계」    백룸. 형광등이 꺼지지 않고 그림자가 없다.
지역 3  섹터 7~9   「붉은 성소」    검붉고 뜨겁다. 벽이 살이다.
```

지역이 바꾸는 것은 셋이다.

| | 바꾸는 것 | 어디서 |
|---|---|---|
| 팔레트 | 벽·바닥·천장은 직접 지정, 소품은 **재사상(remap)** | `view3d/Biome.ts` |
| 공기 | 안개 색·농도, 앰비언트, 손전등 세기, 천장 형광등 | 〃 |
| 복도 종류 | 그 지역이 뽑는 `CorridorKind` 목록 | 〃 |

형태는 한 벌만 유지한다. 소품 색은 원래 값의 **상대 명암만** 남기고 지역 팔레트
안으로 다시 깔린다 — 그래서 기물 하나를 고치면 세 지역이 함께 고쳐진다.

지역이 바뀌는 순간은 **이동 구간의 경계뿐**이다. 걷는 도중에 벽 색이 갈리면 그건 컷이다.

#### 9.0.1 지역 보스

각 지역의 **마지막 섹터(3·6·9) 보스 노드**에 그 지역의 고유 보스가 선다.
나머지 보스 노드는 지금까지처럼 아키타입 보스다. 지역 보스 문은 갈림길이 아니다 —
양쪽 문 뒤에 같은 것이 서 있고, 위험도는 언제나 ◆◆◆ 다.

설계 문법은 포피 플레이타임에서 빌린다: **큰 얼굴 하나, 단순한 덩어리, 과장된 팔.**
무서운 것은 디테일이 아니라 **크기가 틀린 것**이다. 셋 다 실루엣만 잘라 놔도 구별된다.

| 지역 | 보스 | 실루엣 | HP 배율 |
|---|---|---|---|
| 1 강철 하복부 | 깜빡이 | 배전함 몸통 · 명멸하는 전구 눈 두 개 · 그릴 입 · 늘어진 케이블 팔 | ×2.3 |
| 2 노란 층계 | 관리인 | 벽지와 같은 색의 거인 · 검은 눈 두 개 · 초승달 입 · 바닥을 쓰는 긴 팔 | ×2.6 |
| 3 붉은 성소 | 어머니 | 천장에서 늘어진 종 모양 살덩이 · 큰 눈 하나 · 세로로 벌어진 입 · 촉수 여섯 | ×1.95 |

배율이 어머니만 낮은 것은 섹터 9 의 기저 HP 가 이미 섹터 3 의 33배이기 때문이다.
실측(런 200판)에서 사망 노드 1위는 어머니(21회), 2위가 관리인 계열이다 — 지역 보스
셋이 각 지역에서 가장 위험한 한 판이 되도록 맞췄다.

**보스는 맞을 때마다 말한다.** 대사는 무작위가 아니라 **순서대로** 돈다 — 무작위로
뽑으면 같은 줄이 연달아 나와 '반응' 이 아니라 소음이 된다. 순서대로 돌면 맞을수록
말이 무너지는 구성을 쓸 수 있고, 셋 다 뒤로 갈수록 문장이 짧아진다.
HP 가 처음 절반 아래로 내려가면 그 줄을 끊고 중간 대사가 끼어든다.

#### 9.0.2 완주와 크레딧

세 지역을 전부 넘어서면 런이 끝나고 **크레딧이 오른다** — 지역 이름과 거기서 마주친
것들을 순서대로 다시 올려 준다. 완주는 이 게임에서 가장 드문 사건인데 예전에는
결과 화면의 '완주' 두 글자로 끝났다. 통계표가 승리의 보상이 되면 이긴 사람이 자기가
무엇을 지나왔는지 되짚을 자리가 없다.

### 9.1 전체 구조

```
섹터 1개 =
   노드1 (갈림길 선택) → 전투 → 보상방
   노드2 (갈림길 선택) → 전투 → 보상방
   노드3 (갈림길 선택) → 전투 or 정비소/성소/이벤트
   노드4 : 섹터 보스 (고정, 갈림길 없음) → 대형 보상방
```

가운데 한 칸(노드3)의 리듬은 **지역이** 정한다: 1섹터 정비소 → 2섹터 폐허 →
3섹터 성소 → 지역 보스.

한 섹터 = 약 3~5분. 9섹터 = 30~45분. **한 손으로, 지하철 한 구간에서 끝난다.**

### 9.2 갈림길 (Branch)

노드에 도달하면 **어두운 복도 끝에 문 2개**가 보인다. 각 문 위에는 스프레이로 표식이 그려져 있다.

```
┌──────────────┐   ┌──────────────┐
│   ◆ ◇ ◇      │   │   ◆ ◆ ◆      │
│  배회자       │   │  주자 · 돌진  │
│  보상: ●○○    │   │  보상: ●●●   │
└──────────────┘   └──────────────┘
```

**위험도 T (1~3)** 가 아래 둘을 동시에 결정한다.

| | T=1 (◆) | T=2 (◆◆) | T=3 (◆◆◆) |
|---|---|---|---|
| 적 HP 배율 | ×1.00 | ×1.25 | ×1.55 |
| 접근 속도 | +0 | +1 | +2 |
| 패시브 | 없음 | 30% 확률 1개 | 확정 1개 |
| 보상 레어도 (일반/희귀/영웅/유물) | 70/26/4/0 | 45/40/14/1 | 20/45/30/5 |
| 보상 개수 | 3택1 | 3택1 | **4택1** |
| 탄피 보너스 | +0 | +15 | +35 |

- 한 노드에서 제시되는 두 문의 T는 **항상 서로 다르다** (예: 1 vs 2, 2 vs 3).
- 표시되는 정보: 적 아키타입, 패시브 아이콘, 보상 레어도 점 표기. **HP 수치는 미표기** (문을 열면 공개).
  → "얼마나 셀지"가 아니라 "어떤 종류의 문제인지"로 판단하게 만든다. 계산이 아니라 빌드 자신감의 문제로.

> **설계 의도**: 슬레이 더 스파이어의 맵 선택은 여러 노드 앞을 내다보는 장기 계획이지만,
> 세로 화면 모바일에서 큰 맵을 보여주는 건 UX 재앙이다. **1인칭에서 문 두 개**는
> (a) 화면을 전혀 낭비하지 않고 (b) 3D 씬 그 자체가 UI이며 (c) 선택의 무게가 즉물적이다.
> 대신 장기 계획성이 줄어드는 만큼, 섹터 시작 시 **섹터 보스의 패시브를 미리 공개**해 계획 축을 보존한다.

### 9.3 노드 종류

| 노드 | 빈도 | 내용 |
|---|---|---|
| **교전** | 섹터당 3~4 | 전투 → 보상방 (3택1 무료 + 탄피) |
| **정비소 (Armory)** | 섹터당 1 보장 | 탄피 소비: 탄 구매 / 가방에서 탄 제거 / 탄 등급 승급 / 부착물 구매 |
| **성소 (Reliquary)** | 섹터 3·5·7에 1 | 고레어도 부착물 3종 진열. 비싸다. 보조 레일 확장 구매처 |
| **폐허 (Derelict)** | 섹터당 최대 1 | 이벤트. 아래 6종만 존재 |
| **섹터 보스** | 섹터당 1 | 패시브 확정. 대형 보상 (영웅 이상 2택1 + 탄피 대량) |

### 9.4 이벤트 (정확히 6종)

이벤트는 **"기존 자원을 다른 자원으로 바꾸는 환율표"** 로만 존재한다. 새 규칙을 만들지 않는다.

| 이벤트 | 선택지 |
|---|---|
| **시체 더미** | ⓐ 탄피 +60  ⓑ 무작위 희귀 부착물 획득, 다음 전투 시작 거리 −8m |
| **봉인된 성궤** | ⓐ 가방의 탄 3발을 무작위로 등급 +1  ⓑ 탄창을 무작위 미보유 탄창으로 교체 |
| **고해실** | ⓐ 가방에서 탄 2발 영구 제거(무료)  ⓑ 부착물 1개를 같은 부위 무작위 영웅으로 교체 |
| **불타는 성구** | ⓐ 이번 섹터 내내 사격 시작 온도 +3  ⓑ 탄피 +40 |
| **탄약고 붕괴** | ⓐ 무작위 탄 6발 획득 (등급 무작위)  ⓑ 가방 전체를 절반으로 압축(무작위 제거) |
| **거울 방** | ⓐ 부착물 1개 복제(같은 부위 슬롯이 비어야 함 → 보조 레일 필요)  ⓑ 보조 레일 +1 |

> 6종인 이유: 섹터 9개 × 최대 1회 = 9회 조우인데, 6종이면 반복이 1~2회로 제한되고
> 각 이벤트가 "무엇을 포기하고 무엇을 얻는가"를 완전히 다르게 묻는다. (돈/등급/압축/온도/양/슬롯)

### 9.5 보상방

전투 직후, 흔들리는 랜턴 아래 벽에 못박힌 상자가 열린다.

```
┌─────────────────────────────────────┐
│  전리품                     탄피 +47 │
├──────────┬──────────┬───────────────┤
│ [부착물]  │  [탄]     │  [부착물]      │
│ 방열 핀   │ 철갑 Mk.III│  거리계        │
│ 일반      │  —        │  희귀          │
└──────────┴──────────┴───────────────┘
        택 1 (무료) · 건너뛰면 탄피 +20
```

- 3장(위험도 3이면 4장) 중 1개 무료 획득. 슬롯이 차 있으면 교체 여부를 묻는다.
- **건너뛰기 → 탄피 +20**: 아무것도 안 고를 자유에 값을 매겨서, "빌드에 안 맞는 걸 억지로 줍는" 상황을 없앤다.
- 구성: 부착물 2 : 탄 1 비율 기본. 위험도 3에서는 부착물 3 : 탄 1.

## 10. 경제 — 탄피 (Brass)

### 10.1 수입

| 원천 | 금액 | 왜 이걸 보상하는가 |
|---|---|---|
| 전투 승리 | +25 | 기본 소득 |
| 남은 거리 | **1m당 +1** | *빨리 죽여라*. 게임의 핵심 목표와 소득이 정렬 |
| 최고 온도 | 10마다 +2 | *예열해라*. 코어 메커닉 보상 |
| 위험도 보너스 | T2 +15 / T3 +35 | 어려운 문 선택의 즉시 보상 |
| 보상 건너뛰기 | +20 | 빌드 순수성 유지 비용 보전 |

> 소득 원천이 4개뿐이고 **전부 "잘 싸웠다"의 다른 표현**이다.
> 발라트로처럼 "돈을 안 쓰고 이자로 굴린다" 같은 별개의 최적화 게임을 만들지 않는다.
> 이자 시스템은 의도적으로 **없다** (JUSTIFICATION.md §제외 항목 참조).

### 10.2 지출 (정비소 / 성소)

| 항목 | 가격 | 존재 이유 |
|---|---|---|
| 탄 구매 (Mk.I~III) | 12 / 24 / 45 | 덱 보강 |
| **가방에서 탄 제거** | 20 (구매마다 +10) | **덱 압축 = 원하는 탄이 나올 확률.** 가장 중요한 지출처 |
| 탄 등급 +1 승급 | 30 (Mk.IV→V는 70) | 압축의 대안: 같은 장수로 질을 올린다 |
| 부착물 구매 (일반/희귀/영웅) | 35 / 70 / 130 | 슬롯 채우기 |
| **탄창 교체** | 60 | 빌드 방향 전환 |
| **보조 레일 확장** | 1번째 120 / 2번째 220 | 장기 투자. 초반 소비를 억제하는 저축 목표 |
| 완전 회복 (거리 +10, 다음 전투 한정) | 25 | 위험한 문을 고른 뒤의 보험 |

**지출처 7개.** 각각 다른 축(양/질/압축/슬롯/구조/보험)을 담당하며, 어느 것도 다른 것의 상위호환이 아니다.

## 11. 1인칭 이동 구간 (온레일 탐험)

타임 크라이시스 / 터치 더 데드 방식. **입력 없이 카메라가 스플라인을 따라 전진**한다.

### 11.1 목적 (왜 이 구간이 존재하는가)

1. **호흡 조절** — 전투(계산)와 전투 사이에 뇌를 쉬게 한다. 발라트로에는 없는, 이 게임만의 리듬.
2. **정보 전달 채널** — 다음 적의 흔적(피 자국, 긁힌 자국, 뒤집힌 바리케이드)으로 다가올 위협을 예고.
3. **선택의 공간화** — 갈림길이 "메뉴"가 아니라 "복도 끝 두 개의 문"이 되게 한다.
4. **로딩 은폐** — 다음 전투 씬 에셋/좀비 인스턴스를 이 8~15초 동안 준비한다.

### 11.2 구성

- 길이 8~15초. **탭 홀드로 2배속, 더블탭으로 즉시 스킵** (2회차 이후 플레이어 존중).
- 모듈러 프리팹 조립: `복도 / 계단참 / 무너진 사무실 / 배관실 / 주차장 램프 / 성당 잔해` 6종 × 좌우 반전 × 소품 랜덤.
- 조명: **손전등 1개(스포트라이트) + 앰비언트 극소**. 어둠이 곧 렌더링 예산 절감이자 분위기다.
- 이동 중 인터랙션: **없음.** 주울 것도, 볼 것도 강제하지 않는다.
  (이동 구간에 수집 요소를 넣으면 "스킵하면 손해"가 되어 스킵 기능이 무의미해진다.)

## 12. 메타 진행 / 해금

**최소한만 존재한다.**

| 해금 조건 | 해금 내용 |
|---|---|
| 섹터 N 최초 도달 (N=2,4,6,8) | 신규 탄창 M3/M5/M7/M9 이 보상 풀에 추가 |
| 특정 부착물로 전투 승리 누적 | 해당 부착물의 상위 변형 1종 풀 추가 (총 8종) |
| 런 최초 클리어 | **성전 등급 (Litany Rank) 1~8** 난이도 계단 개방 |

성전 등급 (발라트로 Stake 대응):
1. 기본 / 2. 보상방 건너뛰기 보상 없음 / 3. 적 HP +10% / 4. 정비소 가격 +40% /
5. 섹터마다 시작 거리 −2m / 6. 보상 레어도 1단계 하향 / 7. 보스 패시브 2개 / 8. 온도 획득 −15%

> **왜 영구 강화(퍼머넌트 업그레이드)가 없는가**: 로그라이트식 영구 스탯 상승은 "실력이 아니라 시간"으로
> 벽을 넘게 만들어, 매 런의 빌드 결정을 흐린다. 발라트로가 그렇지 않듯 이 게임도 그렇지 않다.
> 해금은 **선택지의 다양성**만 늘리고, **강함**은 늘리지 않는다.

## 13. 실패 · 성공 상태

| 상태 | 조건 | 처리 |
|---|---|---|
| 전투 승리 | 적 HP ≤ 0 | 보상방 |
| **즉사** | 거리 ≤ 0 (좀비 접촉) | 1인칭 시야가 좀비 손에 잡히는 0.8초 연출 → 런 종료 요약 |
| 런 클리어 | 섹터 9 지역 보스 「어머니」 격파 | **크레딧 롤** → 결과 요약 + 엔드리스 계속하기 제안 |
| 이탈 | 앱 종료 / 탭 전환 | **자동 저장.** 노드 단위로 localStorage 스냅샷. 재접속 시 이어하기 |

### 즉사가 유일한 실패 조건인 이유

체력바가 없으면 "관리해야 할 두 번째 자원"이 사라진다. 대신 **거리**가 그 역할을 100% 대체하며,
게다가 거리는 **행동 예산**이기도 하다. 하나의 게이지가 (a) 남은 턴 수 (b) 목숨 두 가지를 동시에 의미하기 때문에
플레이어는 "지금 배출 한 번이 목숨의 몇 퍼센트인가"를 항상 정확히 안다. — 이것이 파라미터 통합의 가장 큰 승리다.

## 14. 설계 원칙 상세

### 14.1 파라미터 예산 (Parameter Budget)

플레이어가 **전투 중 실시간으로 추적하는 숫자**의 총 개수를 **5개 이하**로 고정한다.

| # | 숫자 | 위치 |
|---|---|---|
| 1 | 적 HP (남은 %) | 상단 바 |
| 2 | 거리 (m) | 상단 게이지 + 3D 씬 |
| 3 | 온도 | 하단 게이지 + 총 발광 |
| 4 | 탄창에 넣은 탄 수 / 용량 | 하단 슬롯 |
| 5 | 트레이 잔량 | 하단 카드 |

탄피, 부착물 스택, 소각 더미 개수 등은 **필요할 때만 조회**하는 정보이지 추적 대상이 아니다.

### 14.2 "존재의의" 심사 기준

새 요소를 추가할 때 아래 3문항을 통과해야 한다. 하나라도 실패하면 넣지 않는다.

1. **이것을 제거하면 어떤 결정이 사라지는가?** — 답이 "없음"이면 삭제.
2. **이것이 없을 때 다른 요소가 대신할 수 있는가?** — 대체 가능하면 중복이므로 삭제.
3. **플레이어가 이것을 무시하고도 이길 수 있는가?** — 무시 가능하면 노이즈이므로 삭제.

전체 감사 결과는 [JUSTIFICATION.md](JUSTIFICATION.md).

### 14.3 모바일 세로 우선 원칙

- 모든 상시 조작은 **화면 하단 45% (엄지 도달 영역)** 안에서 끝난다.
- 3D 뷰포트는 상단 55%. 전투 중 카메라는 고정이며 시각 정보는 (적 위치, 총 발광, 이펙트) 3가지뿐.
- 텍스트 최소 크기 13pt. 탭 타겟 최소 44×44pt (iOS HIG).
- **한 손 조작으로 런 전체 완주 가능.**
