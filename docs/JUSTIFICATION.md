# 존재의의 감사표 (Justification Audit)

> 요구사항: *"모든 요소에 존재의의가 완벽하게 명확한 게임."*
> 이 문서는 **채택한 모든 요소가 왜 필요한지**와 **채택하지 않은 것이 왜 불필요한지**를 기록한다.
> 새 요소를 추가하려는 사람은 먼저 이 문서의 §3 심사표를 통과시켜야 한다.

---

## 1. 채택 요소 감사

각 요소에 대해 세 질문에 답한다.
**Q1** 제거하면 어떤 *결정*이 사라지는가 · **Q2** 다른 요소가 대체 가능한가 · **Q3** 무시하고 이길 수 있는가

| 요소 | Q1: 사라지는 결정 | Q2: 대체 가능? | Q3: 무시 가능? | 판정 |
|---|---|---|---|---|
| **온도(곱셈)** | "무엇을 먼저 쏠까" — 게임 전체 | 불가 (곱셈 축이 사라지면 덧셈 누적 게임이 됨) | 불가 | **필수** |
| **데미지(칩)** | "무엇을 마지막에 쏠까" | 불가 (곱해질 대상이 없어짐) | 불가 | **필수** |
| **거리(m)** | "한 번 더 고를 여유가 있나" + 목숨 | 불가. HP/턴수 두 자원을 하나로 압축한 결과물 | 불가 | **필수** |
| **탄종 4종** | "어떤 역할의 탄을 뽑을까" | 불가. 곱수/피해/자원/접착 4역할은 최소 구성 | 불가 | **필수** |
| **등급 5단계** | "질을 올릴까 양을 늘릴까" | 부분 대체 가능(탄종만으로도 굴러감)하나, 정비소 승급·등급 조건 부착물의 존재 기반 | 가능하나 손해 | **채택** |
| **탄창 용량** | "곱셈을 몇 번 굴릴까" | 불가. 폭/깊이 빌드 축의 원천 | 불가 | **필수** |
| **트레이 크기** | "얼마나 넓게 보고 고를까" | 불가. 정보/운 통제 축 | 가능하나 손해 | **채택** |
| **부위 고정 슬롯** | "네 축 중 어디를 먼저 채울까" | 자유 슬롯으로 대체 시 데미지 편중 지배전략 발생 | 불가 | **필수** |
| **보조 레일** | "조커 순서를 어떻게 놓을까" | 하드포인트만으론 조합의 자유가 없음 | 가능(0칸 시작) | **채택** |
| **적 접근속도 S** | "이 전투를 몇 행동에 끝낼까" | HP만으로는 전투 성격이 균일해짐 | 불가 | **필수** |
| **적 패시브** | "이 빌드로 이 문에 들어갈까" | 불가. 빌드 고착 방지 장치 | 불가 (보스전) | **필수** |
| **갈림길 위험도** | "위험을 살까 안전을 살까" | 불가. 유일한 메타 결정 지점 | 불가 (반드시 선택) | **필수** |
| **탄피** | "압축/질/슬롯/구조 중 무엇에 투자할까" | 무료 보상만으론 덱 압축 수단이 없음 | 가능(모으기만 해도 됨)하나 큰 손해 | **채택** |
| **온레일 이동** | (결정 없음) 대신 리듬·예고·로딩 은폐 3역할 | 로딩 화면으로 대체하면 예고와 리듬을 잃음 | 스킵 가능 (의도적) | **채택 — 비결정 요소로서 유일한 예외** |
| **축성탄 와일드** | "조건부 부착물을 안정적으로 켤까" | 불가. 조건 빌드의 신뢰도 보증 | 가능 | **채택** |
| **HE 넉백** | "지금 시간을 살까 피해를 살까" | 불가. 거리를 되사는 유일한 수단 | 가능 | **채택** |

### 유일한 예외에 대한 해명 — 온레일 이동 구간

이 구간은 **플레이어 결정을 만들지 않는다.** 심사 Q1을 통과하지 못한다.
그럼에도 채택한 이유는, 이 게임이 **인지 부하가 매우 높은 계산 게임**이기 때문이다.
전투가 연속되면 40분 세션을 버틸 수 없다. 이 구간은 **회복 시간이자 예고 채널이며 로딩 은폐**다.
단, 결정을 만들지 않으므로 **스킵을 항상 허용**한다. "스킵하면 손해"인 요소는 절대 넣지 않는다.

## 2. 의도적으로 제외한 것들

| 제외 항목 | 흔한 게임에서의 모습 | 제외 이유 |
|---|---|---|
| **명중률 / 조준** | FPS의 기본 | 결정이 아니라 실행. 온레일 1인칭에서 조준은 "잘 눌렀나" 테스트일 뿐이고, 덱빌딩의 계산을 방해한다 |
| **반동 / 탄속 / 탄도 낙차** | 밀리터리 슈터 | 플레이어가 통제할 수단이 없으면 순수 노이즈. 통제 수단을 주면 액션게임이 되어 장르가 바뀜 |
| **플레이어 HP / 아머** | 대부분의 게임 | 거리 게이지가 완전히 대체한다. HP를 추가하면 "관리할 자원"이 2개가 되면서 거리의 절박함이 희석됨 |
| **×멀트 (곱셈 배율)** | 발라트로 | 곱셈 축이 2개가 되면 연산 순서 학습 비용이 발생. 온도 하나로 좁힌 것이 이 게임의 정체성 |
| **탄약 고갈** | 서바이벌 호러 | 가방이 비면 회수·재셔플한다. 고갈은 "이길 수 없는 판"을 만들 뿐 결정을 만들지 않는다 |
| **이자 / 저축 시스템** | 발라트로의 돈 | 최적 소비 타이밍이라는 *별개의 게임*이 생긴다. 이 게임의 결정 예산은 이미 순서 배열에 다 쓰였다 |
| **영구 강화 (메타 스탯)** | 로그라이트 일반 | "시간으로 벽 넘기"는 매 런의 빌드 결정을 흐린다. 해금은 **선택지**만 늘리고 **강함**은 안 늘린다 |
| **소모품 / 인벤토리** | 대부분의 로그라이크 | 관리 대상이 하나 더 생긴다. 필요한 효과는 전부 부착물·탄창·이벤트로 흡수 가능 |
| **다중 타겟 / 관통** | 좀비 게임의 기본 | 타겟팅·스플래시·관통 3개 파라미터를 데려온다. 무리(Horde)를 "HP 공유 단일 개체"로 만들어 시각만 취함 |
| **적 공격 / 피격 패턴** | 액션 게임 | 좀비는 닿으면 즉사. 이분법이라 플레이어는 "몇 행동 안에 끝낼까" 한 질문에만 답하면 된다 |
| **상태이상 (화상·독)** | RPG | 지속 피해 축을 만들려면 턴 개념이 실시간으로 필요. 온도가 이미 "누적 성장"을 담당하므로 중복 |
| **탄 강화/각인 (개별 카드 업그레이드)** | 발라트로의 카드 강화 | 등급 승급이 같은 역할을 더 단순하게 한다. 24발 각각의 상태를 기억시키는 건 파라미터 예산 파산 |
| **무기 교체 (여러 총)** | 슈터 일반 | 총 = 부착물 5칸의 총합. 총 자체를 바꾸면 부착물 시스템이 무의미해진다. **총은 한 자루뿐이다** |
| **동료 / 소환수** | 로그라이크 | 플레이어가 통제하지 않는 데미지원. 순서 게임의 계산 결과를 흐린다 |
| **랭킹 / 온라인** | — | 정적 호스팅 제약 + 초기 범위. 시드 공유로 경쟁 욕구는 충족 |
| **스토리 컷신** | — | 세계관은 규칙에 봉사하는 최소한만. 컷신은 스킵 대상이 되고 리듬을 깬다 |
| **자동 최적 배치 버튼** | 편의 기능 | **게임 자체를 삭제하는 기능.** 대신 실시간 예상 피해로 학습을 돕는다 |

## 3. 신규 요소 심사표 (앞으로 무언가를 추가할 때)

새 시스템·파라미터·콘텐츠를 제안할 때 아래를 채워야 한다. 한 칸이라도 못 채우면 채택하지 않는다.

```
[ 제안 이름 ]

1. 이것이 만드는 플레이어의 결정을 한 문장으로:
   "플레이어는 ______ 와 ______ 중에서 고르게 된다."

2. 이 결정이 기존 요소로 이미 가능한가?  (예 → 기각)

3. 플레이어가 전투 중 추적해야 할 숫자가 늘어나는가?
   (늘어난다면 → 기존 5개 중 무엇을 뺄 것인가?)

4. 이것을 완전히 무시하고 런을 클리어할 수 있는가?  (예 → 노이즈, 기각)

5. 툴팁 한 줄(공백 포함 40자)로 설명 가능한가?  (아니오 → 기각 또는 단순화)

6. 어떤 적 패시브가 이것을 봉쇄하는가?  (없다면 → 지배 전략 위험)
```

### 심사 예시 — "탄 관통 (Penetration)" 제안

| 항목 | 답 | 결과 |
|---|---|---|
| 1. 결정 | "플레이어는 단일 고피해와 다수 관통 중에서 고른다" | OK |
| 2. 기존 대체 | 무리(Horde)는 HP 공유 단일 개체이므로 관통의 이득이 없다 | **기각** |
| — | 관통을 쓰려면 다중 타겟이 필요 → 타겟팅 파라미터 추가 → 3번 위반 | **최종 기각** |

### 심사 예시 — "축성탄 와일드" 제안

| 항목 | 답 |
|---|---|
| 1. 결정 | "플레이어는 안정적인 조건 발동과 높은 기본 데미지 중에서 고른다" |
| 2. 기존 대체 | 없음. 조건부 부착물의 발동률을 통제할 수단이 이것뿐 |
| 3. 추적 숫자 | 늘지 않음 (탄 속성) |
| 4. 무시 가능? | 가능하나, 조건 빌드는 성립하지 않음 → 유의미 |
| 5. 툴팁 | "축성탄은 모든 탄종으로 취급된다" (17자) |
| 6. 봉쇄 패시브 | **성별 거부 (Anathema)** |
| 판정 | **채택** |

## 5. 이 게임이 성공했는지 판정하는 기준

| 질문 | 성공 기준 |
|---|---|
| 순서가 정말 중요한가? | 동일 5발의 **최선 배열 / 최악 배열 데미지 비가 평균 2.5배 이상** |
| 갈림길이 진짜 선택인가? | 위험도 3 선택률이 **35~65%** 구간 (한쪽으로 쏠리면 환율이 틀린 것) |
| 빌드가 갈리는가? | 클리어 런의 **아키타입 분포에서 최다 아키타입이 35% 미만** |
| 배울 것이 있는가? | `optimal` 봇과 `greedy` 봇의 생존률 격차가 **섹터가 오를수록 벌어진다** |
| 파라미터가 과하지 않은가? | 신규 플레이어가 **튜토리얼 없이 3전투 안에 "예열 후 피니셔"를 스스로 발견** |
| 모바일에서 굴러가는가? | iPhone 12 세로에서 **60fps, 한 손 조작으로 런 완주** |
